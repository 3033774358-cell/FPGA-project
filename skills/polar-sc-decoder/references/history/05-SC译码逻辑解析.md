你说的“SC译码逻辑”通常指的是 Polar码（极化码）的 Successive Cancellation（SC，连续消除）译码算法逻辑。下面从原理、数据流和硬件实现逻辑三个层面解释。

1. SC译码基本思想
Polar码编码：
$x=uG_N$
其中：


$u$：信息比特 + 冻结比特


$G_N$：极化矩阵


$x$：发送码字


接收端得到：
$y=(y_0,y_1,...,y_{N-1})$
经过信道：
$L_i=\ln\frac{P(y_i|0)}{P(y_i|1)}$
得到初始LLR。
SC译码按照比特顺序：
$\hat{u}_0,\hat{u}_1,...,\hat{u}_{N-1}$
逐个判决。
核心思想：

当前比特译码时，利用之前已经译出的比特作为已知条件。


2. SC译码核心计算逻辑
SC译码主要由两个递归函数组成：
(1) F函数（左子树）
用于计算左半部分LLR：
$L_l=f(L_a,L_b)$
精确形式：
$f(a,b)=
\ln
\frac{1+e^{a+b}}
{e^a+e^b}$
硬件常用近似：
$f(a,b)
=
sign(a)sign(b)
\min(|a|,|b|)$
也叫：
Min-Sum算法

例如：
代码a=3b=-2sign(a)*sign(b)=-1min(|3|,|-2|)=2输出：-2

(2) G函数（右子树）
右侧LLR：
$L_r=g(a,b,\hat{u})$
公式：
$g(a,b,u)
=
(-1)^u a+b$
其中：


$u=0$


$g=a+b$


$u=1$


$g=-a+b$

例如：
代码a=4b=1u=1g=-4+1=-3

3. SC译码树结构
以N=8为例：
代码                L0                 |        ----------------        |              |       f              g        |              |    --------       --------    |      |       |      |    f      g       f      g    |      |       |      | u0,u1  u2,u3   u4,u5  u6,u7
译码过程：
代码输入LLR ↓计算左节点 ↓译码左半比特 ↓根据左半结果计算右节点 ↓译码右半比特 ↓输出全部u

硬件一般使用FSM：
代码START ↓LOAD LLR ↓F计算 ↓LEFT DECODE ↓G计算 ↓RIGHT DECODE ↓CHECK BIT ↓OUTPUT ↓END

这两个问题是理解 SC（Successive Cancellation）译码的关键。很多人第一次看 SC 树都会疑惑：为什么无缘无故把码字拆成左右子树？LLR 又是怎么来的？
我从 Polar 码编码结构反推 SC 译码逻辑。

一、左右子树的意义是什么？为什么要这样划分？
1. 根本原因：Polar码本身就是递归结构
Polar码的生成矩阵：
$G_N=F^{\otimes n}$
其中：
$F=
\begin{bmatrix}
1&0\\
1&1
\end{bmatrix}$
例如最简单的 N=2：
输入：
$(u_0,u_1)$
编码：
$x_0=u_0\oplus u_1$
$x_1=u_1$
结构：
代码       u0      u1        \      /         XOR          |       x0,x1
可以看到：


$u_0$ 影响两个输出


$u_1$ 只影响第二个输出



当 N 增大，例如 N=8：
Polar编码矩阵实际上是不断重复：
代码N=8              编码                |        ----------------        |              |       N=4            N=4        |              |    --------       --------    |      |       |      |   N=2    N=2    N=2    N=2
所以译码自然也形成树：
代码                 Root                  |        ------------------        |                |      左子树           右子树

2. 左右子树分别代表什么？
假设：
$u=[u_0,u_1,u_2,u_3]$
编码：
$x_0=u_0\oplus u_1\oplus u_2\oplus u_3$
$x_1=u_2\oplus u_3$
$x_2=u_1\oplus u_3$
$x_3=u_3$
SC译码：
先恢复：
$u_0,u_1$
再恢复：
$u_2,u_3$
也就是：
代码             y0 y1 y2 y3                  |              根节点          ----------------          |              |      左半信息       右半信息      u0,u1          u2,u3

为什么必须先左后右？
因为右子树译码需要左子树结果。
原因：
右侧LLR：
$g(a,b,u)$
里面有：
$u$
例如：
$g(a,b,u)=(-1)^u a+b$
如果不知道左边：
$u_0$
右边根本无法计算。
所以：
SC流程：
代码先译码左边↓得到已知比特↓辅助右边译码
这就是：
Successive Cancellation（连续消除）

二、信道LLR $L_i$ 是怎么计算的？
这个是SC译码的输入。
假设发送：
$x_i\in\{0,1\}$
经过信道：
接收到：
$y_i$
SC不直接看y，而转换成：
$L_i$

1. LLR定义
$L_i=
\ln
\frac{P(y_i|x_i=0)}
{P(y_i|x_i=1)}$
含义：


L>0


说明：
更可能发送0


L<0


说明：
更可能发送1


|L|越大


可靠性越高

2. 以AWGN信道为例
实际通信中：
$y=x+n$
其中：


$x$：发送符号


$n$：高斯噪声


注意：
BPSK映射：
$0\rightarrow +1$
$1\rightarrow -1$
例如：
发送0：
代码x=+1接收：y=0.8
说明：
接近+1。

3. AWGN下LLR推导
概率：
$P(y|x)
=
\frac1{\sqrt{2\pi\sigma^2}}
e^{-\frac{(y-x)^2}{2\sigma^2}}$
代入：
$L=
\ln
\frac{
e^{-\frac{(y-1)^2}{2\sigma^2}}
}
{
e^{-\frac{(y+1)^2}{2\sigma^2}}
}$
指数相减：
$L=
\frac{(y+1)^2-(y-1)^2}
{2\sigma^2}$
展开：
$(y+1)^2=y^2+2y+1$
$(y-1)^2=y^2-2y+1$
得到：
$L=
\frac{4y}{2\sigma^2}$
最终：
$\boxed{
L=\frac{2y}{\sigma^2}
}$

4. 举例
假设：
噪声：
$\sigma^2=0.5$
接收：
$y=0.8$
那么：
$L=
\frac{2\times0.8}{0.5}$
$L=3.2$
表示：
代码强烈认为发送的是0

如果：
$y=-0.5$
则：
$L=-2$
表示：
代码更可能发送1

5. LLR进入SC之后发生什么？
信道输出：
代码y0 y1 y2 y3↓LLR计算↓L0 L1 L2 L3↓        f     左子树LLR↓译码左比特↓        g     右子树LLR↓译码右比特

6. 一个非常直观的理解
可以把Polar码看成：
代码发送端：信息 | |  混合 ↓多个观察值接收端：多个观察值 | |  逐层拆解 ↓恢复原始信息
左右子树其实就是：
编码时混合过程的逆过程。
左子树负责：

提取“经过异或混合后的公共信息”

右子树负责：

利用左侧已经恢复的信息，消除干扰后恢复剩余信息


最核心的三个公式：
信道LLR：
$\boxed{
L_i=\ln\frac{P(y_i|0)}{P(y_i|1)}
}$
左节点：
$\boxed{
f(a,b)=sign(a)sign(b)\min(|a|,|b|)
}$
右节点：
$\boxed{
g(a,b,u)=(-1)^ua+b
}$
这三个公式就是 SC 译码硬件里的核心。
如果继续深入，下一步应该理解 “为什么 f 函数能把两个信道合并成一个更可靠的信道，以及 Polar 极化过程到底如何产生好信道和坏信道”，这是理解冻结位和SC性能的关键。
