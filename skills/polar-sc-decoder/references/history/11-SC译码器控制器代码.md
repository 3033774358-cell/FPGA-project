============================================================
二、编码器已经确认的数学关系
============================================================

现有编码核心模块为：

polar_butterfly.v

编码关系为：

d = u · F^(⊗n)

其中没有 bit reversal。

蝶形每级执行：

stage_net[gs][gi+gj]
    = x[gi+gj] XOR x[gi+gj+M]

stage_net[gs][gi+gj+M]
    = x[gi+gj+M]

M = 1 << gs

N=4时编码展开为：

d0 = u0 XOR u1 XOR u2 XOR u3
d1 = u1 XOR u3
d2 = u2 XOR u3
d3 = u3

编码器串行输出顺序为：

d[0] → d[1] → ... → d[N-1]

编码端 u 按自然索引装配：

u[0]、u[1]、...、u[N-1]

冻结位位置填0，信息位按照输入序列顺序填入。

已经检查确认：

1. 编码蝶形 XOR 方向正确；
2. 没有隐含 bit reversal；
3. u_sh 高位窗口搬到 u_bottom 后，自然索引没有反转；
4. 当前 SC 根节点配对方式与编码图一致；
5. SC 根 beta 最终应等于编码码字 d。

SC 对 N=4 的根配对必须是：

left0 = f(alpha0, alpha2)
left1 = f(alpha1, alpha3)

不能写成：

f(alpha0,alpha1)
f(alpha2,alpha3)

右节点为：

right0 = g(alpha0,alpha2,beta_left[0])
right1 = g(alpha1,alpha3,beta_left[1])

beta合并关系：

parent_beta[i]
    = left_beta[i] XOR right_beta[i]

parent_beta[i+half]
    = right_beta[i]

因此N=4根beta为：

beta_root[0] = d0
beta_root[1] = d1
beta_root[2] = d2
beta_root[3] = d3

三、现有完整编码链
============================================================

编码顶层是：

polar_encode_chain.v

它包含：

1. 类型3/4的CRC24B、码块分段、末块细分；
2. 类型2查表分段；
3. frozen_gen生成冻结集；
4. 串行装配u；
5. polar_butterfly执行极化编码；

7. 串行输出m_valid、m_bit。

完整编码链的testbench是：

该TB使用克罗内克矩阵行异或作为编码黄金模型，并验证多种分段、码率和随机案例。

已发现但暂不影响合法配置的问题：

1. ftype2=1时，tab24只支持r16=10、12、14，即R=5/8、3/4、7/8；
   其他MCS组合会得到K=0，正式系统应限制输入或加入非法配置处理。

2. polar_encode_chain虽然有NMAX参数，但u_bottom使用固定切片：
   u_sh[1023:512]等，因此当前实际上固定NMAX=1024。

3. 编码TB中的可靠度序列Qtb直接读取DUT内部ROM，因此可以验证编码链内部一致性，但不能独立证明附录C可靠度ROM本身抄写正确。

module sc_pe #(
    parameter integer W = 10

5. sc_datapath.v
------------------------------------------------------------

这是当前B数据通路顶层，已经给出完整版本。

内部实例化：

sc_beta_mem

功能：

1. 根据外部控制读取两个LLR；
2. 调用sc_pe执行f或g；
3. 将PE结果写回LLR存储；
4. 读取两个beta；
5. 支持四种beta写入来源；
6. 叶节点判决同时写beta_mem和uhat_mem；

beta写入模式：

2'b00：直接写beta_wr_data
2'b01：beta_rd_data_a XOR beta_rd_data_b
2'b10：直接写beta_rd_data_a
2'b11：直接写beta_rd_data_b

叶节点判决：

leaf_decision =
    leaf_frozen
    ? 1'b0
    : llr_rd_data_a[INT_W-1];

beta写端口只有一个，因此优先级为：

leaf_decision_en > beta_wr_en

正常正式控制器不应在同周期同时发两种写请求。

sc_datapath本身不负责：

1. SC树遍历；
2. 地址生成；
3. f/g时序；
4. 叶节点索引；
5. 冻结集生成；
6. beta回传调度；
7. 何时启动输出。

// sc_decoder.v -- 极化码 SC(逐次消除)译码器内核 (可综合, Verilog-2001)
// -----------------------------------------------------------------------------
// 对应编码器 polar_encoder / polar_butterfly 的"反向": 编码算 u -> d;
// 本模块从信道 LLR(软信息)按比特顺序逐个"消除式"判决, 还原出 û。
//
// 算法(标准 SC, 二叉树递归, 与编码同一张 log2(N) 级蝶形因子图):
//   decode(层块长 M, 该节点 LLR alpha[0..M-1]):
//     M==1:  叶子, 冻结位 û=0; 否则硬判 û = (alpha<0)
//     否则:  half=M/2
//            左孩子 LLR:  aL[k] = f(alpha[k], alpha[k+half])           (min-sum)
//            beta_L = decode(half, aL)
//            右孩子 LLR:  aR[k] = g(alpha[k], alpha[k+half], beta_L[k]) (部分和 g)
//            beta_R = decode(half, aR)
//            合并回传:    beta[k]=beta_L[k]^beta_R[k];  beta[k+half]=beta_R[k]
//   f = sign(a)·sign(b)·min(|a|,|b|);   g(a,b,β)= (β? b−a : b+a) (饱和)
//   叶子按访问顺序即 û 下标 0..N-1, 冻结掩码 frozen[下标] 决定冻结/信息。
//
// 硬件实现(单 PE, 内存化, 面积随 N 温和增长, 必然可综合):
//   - 堆内存 2N-1 字: 层 lvl(块长 2^lvl)首址 OFF(lvl)=2N-2^(lvl+1),
//     alpha[]=LLR(有符号 LW 位), pbeta[]=部分和(1 位)。层 n=信道 LLR(N 个)。
//   - FSM 用一个"层指针 cur + 每层相位 ph[] + 元素计数 k"展开上面的递归
//     (树深 <= 10, cur 只在相邻层 ±1 移动, 无需真正的调用栈)。
//   - 每拍只做一个元素的 f 或 g 或合并 -> 单读写口, 关键路径极短, 时序好收敛。
//     时延约 1.5·N·log2(N) 拍。需要更快时可加并行 PE(与编码器瘦身思路对称)。
//
// 参数: N 为 2 的幂(spec 取 {64,128,256,512,1024}); LW = LLR 定点位宽(含符号)。
// 端口: start 在 busy=0 被接受; done 单拍脉冲与 û 有效同拍; u_hat 保持到下次译码。
// 说明: 无速率匹配(星闪 E_r=N_r), 本内核处理"单个码块"; 解级联/解分段/CRC 校验
//       为外层(复用编码器分段/CRC 逻辑的镜像), 后续单独实现。
// =============================================================================
module sc_decoder #(
    parameter integer N  = 256,       // 码长, 2 的幂 (>=2)
    parameter integer LW = 8          // LLR 定点位宽 (含符号)
)(
    input  wire                clk,
    input  wire                rst_n,     // 异步低有效复位
    input  wire                start,     // busy=0 时被接受
    input  wire [N-1:0]        frozen,    // 1=冻结(û=0), 0=信息位; 按 û 下标
    input  wire [N*LW-1:0]     llr_in,    // N 个信道 LLR, 第 i 个=llr_in[i*LW +: LW] (有符号)
    output reg                 busy,
    output reg                 done,      // 单拍脉冲
    output reg  [N-1:0]        u_hat      // 判决出的 û 向量 (冻结位=0)
);
    // ---- 编译期 log2 (Verilog-2001 常量函数, 不用 $clog2) ----
    function integer clog2;
        input integer value;
        integer v;
        begin
            v = value - 1;
            clog2 = 0;
            while (v > 0) begin
                v = v >> 1;
                clog2 = clog2 + 1;
            end
        end
    endfunction

    localparam integer SMAX = clog2(N);              // = log2(N) = 树深 n (>=1)
    localparam integer NTOT = 2*N - 1;               // 堆内存字数
    localparam signed [LW-1:0] PMAX   = (1 << (LW-1)) - 1;  // 饱和幅度 = 2^(LW-1)-1
    localparam signed [LW:0]   SAT_HI =  ((1 << (LW-1)) - 1);   // g 饱和上界 (含符号扩展)
    localparam signed [LW:0]   SAT_LO = -((1 << (LW-1)) - 1);   // g 饱和下界

    localparam [1:0] PH_F = 2'd0, PH_G = 2'd1, PH_C = 2'd2;

    // ---- 堆内存: (lvl,pos) -> 索引 OFF(lvl)+pos, OFF(lvl)=2N-2^(lvl+1) ----

    integer         k;                   // 当前操作内元素计数 0..half-1

    reg  [1:0]      ph [0:SMAX];         // 每层相位 (递归栈)

    reg                 dec;

    //      全部路径都赋值(顶部给默认), 无 latch; cur=0 时不去读内部层, 防越界。
    always @* begin
        half   = 0;
        base_p = 0;
        base_c = 0;
        a_up   = {LW{1'b0}};
        a_lo   = {LW{1'b0}};
        a_leaf = alpha[NTOT-1];                      // 叶子 LLR (OFF(0), 恒有效)

            base_p = (2*N) - (2 << cur);             // OFF(cur)
            base_c = (2*N) - (1 << cur);             // OFF(cur-1) = 2N-2^cur
            a_up   = alpha[base_p + k];
            a_lo   = alpha[base_p + k + half];
        end
    end

    // ---- min-sum f 运算 ----
    function signed [LW-1:0] f_op;
        input signed [LW-1:0] a;
        input signed [LW-1:0] b;
        reg signed [LW-1:0] ma, mb;
        reg s;
        begin
            ma = a[LW-1] ? -a : a;       // |a| (输入保持在 [-PMAX,PMAX], 不会取到最负值)
            mb = b[LW-1] ? -b : b;       // |b|
            s  = a[LW-1] ^ b[LW-1];      // 结果符号
            if (ma <= mb) f_op = s ? -ma : ma;
            else          f_op = s ? -mb : mb;
        end
    endfunction

    // ---- g 运算 (含饱和到 [-PMAX,PMAX]) ----
    function signed [LW-1:0] g_op;
        input signed [LW-1:0] a;
        input signed [LW-1:0] b;
        input               bta;
        reg signed [LW:0]   s;           // 多一位防溢出
        begin
            if (bta) s = $signed({b[LW-1], b}) - $signed({a[LW-1], a});
            else     s = $signed({b[LW-1], b}) + $signed({a[LW-1], a});
            if      (s > SAT_HI) g_op =  PMAX;
            else if (s < SAT_LO) g_op = -PMAX;
            else                 g_op =  s[LW-1:0];
        end
    endfunction

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            busy  <= 1'b0;
            done  <= 1'b0;
            u_hat <= {N{1'b0}};
            cur   <= 0;
            k     <= 0;
            leaf  <= {SMAX{1'b0}};

            for (i = 0; i < NTOT; i = i + 1) begin

                pbeta[i] <= 1'b0;
            end
        end else begin

            if (start && !busy) begin

            end

verilogfor (i = 0; i < N; i = i + 1) begin    if (dut_datapath.u_beta_mem.beta_mem[i] !== d_ref[i]) begin        $display(            "ERROR: root beta[%0d]=%b, expected d[%0d]=%b",            i,            dut_datapath.u_beta_mem.beta_mem[i],            i,            d_ref[i]        );        error_count = error_count + 1;    endend
因为最终根beta必须满足：
Plain textbeta_root[0:63] = d_ref[0:63]
这是一项非常重要的独立检查。

十三、叶节点物理地址不再是固定1536
原N=4：
Plain textdepth2 base = 1536
N=64时叶深度是6，所以叶工作区物理地址是：
Plain textdepth6 base = 2016
正式controller会自动生成：
verilogleaf_beta_wr_addr = 11'd2016;
因此testbench不能再写死检查：
verilogbeta_mem[1536]
N=64叶子临时判决位置应该是：
verilogbeta_mem[2016]
不过这个位置会被每个叶节点重复覆盖，所以系统级测试没有必要逐叶检查该地址。重点检查：
Plain textu_hat[0:63]根beta[0:63]
即可。

十四、仿真超时时间要扩大
N=4译码非常短，N=64需要更多周期。
单PE情况下大致包含：


所有f运算；


所有g运算；


beta保存；


beta两周期合并；


64个叶判决；


64个串行输出。


建议testbench超时先设置得宽松一些，例如：
verilogrepeat (200000)    @(posedge clk);$display("ERROR: simulation timeout");$finish;
不要继续使用N=4时的几十或几百周期超时。

十五、Design Sources和Simulation Sources
正式综合顶层仍然可以先保持：
Plain textsc_datapath
但系统级N=64仿真必须同时加入：
Plain textsc_pe.vsc_llr_mem.vsc_beta_mem.vsc_uhat_mem.vsc_datapath.vsc_controller.v新的N=64 testbench
Simulation Top设置为新的系统testbench，例如：
Plain textsc_b_n64_system_tb
不能再让旧的：
Plain textsc_b_only_system_tb
继续实例化 sc_test_sequencer 后却只修改 n_log=6。

最小修改总结
内容N=64是否需要改sc_pe.v不改sc_llr_mem.v核心逻辑不改sc_beta_mem.v不改sc_uhat_mem.v核心逻辑不改sc_datapath.v通常不改sc_test_sequencer.v不再用于N=64sc_controller.v使用正式通用版testbench里的 N改成64testbench里的 n_log改成6输入LLR数量改成64编码蝶形级数改成6级u_hat接收数量改成64根beta检查数量改成64u_last位置改为63仿真超时明显增大NMAX仍保持1024
第一次N=64验证最重要的三个判据是：
Plain text1. 实际装载了64个LLR，load_done只脉冲一次；2. 输出了64个u_hat，并且u_hat与u_ref完全一致；3. beta_mem[0:63]与编码码字d_ref[0:63]完全一致。

// =============================================================================
// sc_b_only_system_tb.v
// =============================================================================
//
// SC 译码器 B 数据通路完整系统级仿真测试平台
//
// =============================================================================
// 一、测试系统组成
// =============================================================================
//
// 本测试平台实例化：
//
// 1. sc_datapath
//
//    包含：
//
//        sc_pe
//        sc_llr_mem
//        sc_beta_mem
//        sc_uhat_mem
//
// 2. sc_test_sequencer
//
//    仿真专用 N=4 简化 SC 控制器。
//
// =============================================================================
// 二、测试流程
// =============================================================================
//
// 对每一组测试向量：
//
// 1. 给出原始比特：
//
//        u[0]
//        u[1]
//        u[2]
//        u[3]
//
// 2. 根据无 bit reversal 的 Polar 编码关系计算：
//
//        d[0] = u[0] XOR u[1] XOR u[2] XOR u[3]
//        d[1] = u[1] XOR u[3]
//        d[2] = u[2] XOR u[3]
//        d[3] = u[3]
//
// 3. 将编码结果转换为无噪声信道 LLR：
//
//        d[i] = 0：LLR = +40
//        d[i] = 1：LLR = -40
//
//    符号约定：
//
//        LLR >= 0：倾向比特0
//        LLR <  0：倾向比特1
//
// 4. 按照自然顺序串行装载：
//
//        第一个LLR → d[0]
//        第二个LLR → d[1]
//        第三个LLR → d[2]
//        第四个LLR → d[3]
//
// 5. 根节点装载完成后启动 sc_test_sequencer；
//
// 6. sc_test_sequencer 依次发出：
//
//        f微操作
//        g微操作
//        叶节点判决
//        beta更新
//        u_hat输出启动
//
// 7. 通过valid/ready接口接收：
//
//        u_hat[0]
//        u_hat[1]
//        u_hat[2]
//        u_hat[3]
//
// 8. 自动比较译码结果和输入u。
//
// =============================================================================
// 三、测试向量
// =============================================================================
//
// CASE 1：
//
//        frozen = 0011
//
// 即：
//
//        u[0]冻结
//        u[1]冻结
//        u[2]信息位
//        u[3]信息位
//
//        u = 0100
//
// CASE 2：
//
//        frozen = 0011
//        u = 1000
//
// CASE 3：
//
//        frozen = 0000
//        u = 1011
//
// CASE 4：
//
//        frozen = 1111
//        u = 0000
//
// 注意：Verilog向量4'babcd中：
//
//        bit 0 = d
//        bit 1 = c
//        bit 2 = b
//        bit 3 = a
//
// 本测试中的u_vector[i]始终对应u[i]自然索引。
//
// =============================================================================
// 四、N=4说明
// =============================================================================
//
// 正式设计支持的码长为：
//
//        64、128、256、512、1024
//
// 本测试专门使用N=4验证数据通路递归关系。
//
// sc_llr_mem和sc_uhat_mem内部使用：
//
//        N = 1 << n_log
//
// 因而仿真时设置：
//
//        n_log = 2
//
// 可以正常装载和输出4个数据。
//
// N=4只是仿真简化配置，不代表正式控制模块只支持N=4。
//
// =============================================================================
// 五、valid/ready反压
// =============================================================================
//
// u_hat输出期间，本测试会周期性拉低u_ready，验证：
//
//        u_ready=0时不能消耗当前输出；
//        u_index不能递增；
//        u_bit必须保持不变；
//        u_last必须保持不变；
//        output_done不能提前产生。
//
// 最后一个u_hat还会专门暂停一个周期。
//
// =============================================================================

    // 完整N=4译码测试任务
    // =========================================================================
    //
    // 参数：
    //
    //     case_id       ：测试编号
    //     expected_u    ：期望译码结果
    //     frozen_config ：冻结位配置
    //
    // expected_u[i]对应u[i]。
    // =========================================================================

    task run_decode_case;

        input integer case_id;
        input [3:0] expected_u;
        input [3:0] frozen_config;

        reg [3:0] encoded_d;

        reg signed [LLR_W-1:0] current_llr;
        reg signed [INT_W-1:0] expected_internal_llr;

        reg [10:0] expected_output_index;
        reg expected_last;
        reg fire_this_cycle;

        integer input_index;
        integer output_count;
        integer monitor_cycle;
        integer timeout_count;
        integer output_done_count;
        integer last_pause_done;
        integer check_index;

        begin

            case_count = case_count + 1;

            // -----------------------------------------------------------------
            // 计算无bit reversal的N=4 Polar编码结果
            // -----------------------------------------------------------------

            encoded_d[0] =
                expected_u[0] ^
                expected_u[1] ^
                expected_u[2] ^
                expected_u[3];

            encoded_d[1] =
                expected_u[1] ^
                expected_u[3];

            encoded_d[2] =
                expected_u[2] ^
                expected_u[3];

            encoded_d[3] =
                expected_u[3];

            $display("------------------------------------------------------------");
            $display("CASE %0d START", case_id);
            $display("u[3:0]=%b frozen[3:0]=%b d[3:0]=%b", expected_u, frozen_config, encoded_d);

            // -----------------------------------------------------------------
            // 检查测试向量本身是否满足冻结位必须为0
            // -----------------------------------------------------------------

            for (check_index = 0;
                 check_index < 4;
                 check_index = check_index + 1) begin

                check_count = check_count + 1;

                if ((frozen_config[check_index] == 1'b1) &&
                    (expected_u[check_index] != 1'b0)) begin

                    error_count = error_count + 1;

                    $display(
                        "ERROR: CASE %0d has nonzero frozen bit at u[%0d]",
                        case_id,
                        check_index
                    );
                end
            end

            // -----------------------------------------------------------------
            // 配置冻结位和N=4
            // -----------------------------------------------------------------

            @(negedge clk);

            frozen_bits = frozen_config;
            n_log       = 4'd2;

            u_ready = 1'b0;

            // -----------------------------------------------------------------
            // 启动根节点LLR装载
            // -----------------------------------------------------------------

            load_start   = 1'b1;
            llr_in_valid = 1'b0;

            @(posedge clk);
            #1;

            check_count = check_count + 1;

            if (load_busy !== 1'b1) begin
                error_count = error_count + 1;
                $display("ERROR: CASE %0d load_busy did not assert", case_id);
            end

            check_count = check_count + 1;

            if (llr_in_ready !== 1'b1) begin
                error_count = error_count + 1;
                $display("ERROR: CASE %0d llr_in_ready did not assert", case_id);
            end

            @(negedge clk);

            load_start = 1'b0;

            // -----------------------------------------------------------------
            // 串行输入d[0]～d[3]对应的LLR
            // -----------------------------------------------------------------

            for (input_index = 0;
                 input_index < 4;
                 input_index = input_index + 1) begin

                // 在第三个LLR之前插入一个valid暂停周期
                if (input_index == 2) begin

                    llr_in_valid = 1'b0;
                    llr_in       = {LLR_W{1'b0}};

                    @(posedge clk);
                    #1;

                    check_count = check_count + 1;

                    if (load_busy !== 1'b1) begin
                        error_count = error_count + 1;

                        $display(
                            "ERROR: CASE %0d load_busy dropped during valid pause",
                            case_id
                        );
                    end

                    check_count = check_count + 1;

                    if (load_done !== 1'b0) begin
                        error_count = error_count + 1;

                        $display(
                            "ERROR: CASE %0d load_done asserted during valid pause",
                            case_id
                        );
                    end

                    @(negedge clk);
                end

                if (encoded_d[input_index] == 1'b0) begin
                    current_llr = 8'sd40;
                end
                else begin
                    current_llr = -8'sd40;
                end

                llr_in       = current_llr;
                llr_in_valid = 1'b1;

                @(posedge clk);
                #1;

                if (input_index < 3) begin

                    check_count = check_count + 1;

                    if (load_busy !== 1'b1) begin
                        error_count = error_count + 1;

                        $display(
                            "ERROR: CASE %0d load_busy dropped early at input index %0d",
                            case_id,
                            input_index
                        );
                    end

                    check_count = check_count + 1;

                    if (load_done !== 1'b0) begin
                        error_count = error_count + 1;

                        $display(
                            "ERROR: CASE %0d load_done asserted early at input index %0d",
                            case_id,
                            input_index
                        );
                    end
                end
                else begin

                    check_count = check_count + 1;

                    if (load_busy !== 1'b0) begin
                        error_count = error_count + 1;

                        $display(
                            "ERROR: CASE %0d load_busy did not clear after final LLR",
                            case_id
                        );
                    end

                    check_count = check_count + 1;

                    if (load_done !== 1'b1) begin
                        error_count = error_count + 1;

                        $display(
                            "ERROR: CASE %0d load_done did not assert after final LLR",
                            case_id
                        );
                    end
                end

                if (input_index < 3) begin
                    @(negedge clk);
                end
            end

            // -----------------------------------------------------------------
            // 检查根节点LLR自然顺序和符号扩展
            // -----------------------------------------------------------------
            //
            // 这里通过层次化访问读取内部寄存器数组。
            // 该访问只用于testbench。
            // -----------------------------------------------------------------

            for (check_index = 0;
                 check_index < 4;
                 check_index = check_index + 1) begin

                if (encoded_d[check_index] == 1'b0) begin
                    expected_internal_llr = 10'sd40;
                end
                else begin
                    expected_internal_llr = -10'sd40;
                end

                check_count = check_count + 1;

                if (u_datapath.u_sc_llr_mem.llr_mem[check_index]
                    !== expected_internal_llr) begin

                    error_count = error_count + 1;

                    $display(
                        "ERROR: CASE %0d root LLR mismatch address=%0d expected=%0d actual=%0d",
                        case_id,
                        check_index,
                        $signed(expected_internal_llr),
                        $signed(u_datapath.u_sc_llr_mem.llr_mem[check_index])
                    );
                end
            end

            // -----------------------------------------------------------------
            // 停止输入并启动简化控制器
            // -----------------------------------------------------------------

            @(negedge clk);

            llr_in_valid    = 1'b0;
            llr_in          = {LLR_W{1'b0}};
            sequencer_start = 1'b1;

            @(posedge clk);
            #1;

            check_count = check_count + 1;

            if (decode_busy !== 1'b1) begin
                error_count = error_count + 1;

                $display(
                    "ERROR: CASE %0d decode_busy did not assert",
                    case_id
                );
            end

            check_count = check_count + 1;

            if (load_done !== 1'b0) begin
                error_count = error_count + 1;

                $display(
                    "ERROR: CASE %0d load_done remained high for more than one cycle",
                    case_id
                );
            end

            @(negedge clk);

            sequencer_start = 1'b0;

            // -----------------------------------------------------------------
            // 监视u_hat valid/ready输出
            // -----------------------------------------------------------------

            output_count     = 0;
            monitor_cycle    = 0;
            timeout_count    = 0;
            output_done_count = 0;
            last_pause_done  = 0;

            while ((decode_done !== 1'b1) &&
                   (timeout_count < 200)) begin

                // -------------------------------------------------------------
                // 生成ready
                // -------------------------------------------------------------

                if ((u_valid == 1'b1) &&
                    (u_index == 11'd3) &&

1. 冻结序列是否由协议决定？
对标准协议实现：是
例如5G NR的Polar码由 3GPP TS 38.212 规定。协议给出长度1024的通用可靠度序列，编码器再结合本码块的参数构造信息位、冻结位及可能的PC位。3GPP当前仍维护38.212，并在官方规范档案中提供各版本文件。3GPP门户网站+1
但不能简单理解成：
Plain text知道N和K→ 随便冻结N-K位
协议构造通常至少与以下参数相关：
Plain textN：Polar母码长度K：进入Polar编码的有效位数E：速率匹配后的输出长度可靠度序列速率匹配方式是否存在预冻结位置是否存在PC位输入交织方式
因此，同样：
Plain textN = 1024K = 512
如果协议配置、速率匹配方式或PC位规则不同，最终掩码也不一定完全相同。

可靠度序列与冻结掩码的关系
协议中的可靠度序列可以理解为对比特信道可靠性的排序：
Plain text低可靠位置 → 优先冻结高可靠位置 → 优先放信息位
在最简单的条件下：
Plain textE = N无额外预冻结无PC位
可以从长度N的可靠度序列中：
Plain text选最可靠的K个位置作为信息位其余N-K个位置作为冻结位
最后转化为：

但正式协议链不能只根据 N 和 K 手写一个十六进制常量。

// frozen_gen.v  --  由 (N, K) 生成极化码冻结掩码 (依据 spec 附录C 可靠度序列)
// -----------------------------------------------------------------------------
// spec 6.9.1.4: 码长 N、信息位数 K 时, 在可靠度排序序列 Q_0^{N-1} 中取"后 K 个"
// (可靠性最高) 索引作为非冻结(信息)集, 前 N-K 个作为冻结集. 且长为 N 的序列是
// 全序列 Q_0^{Nmax-1} 中"比特索引 < N"的子序列 (嵌套性).
//
// 实现: 从最高可靠度秩 (rank=NMAX-1) 向下扫描可靠度 ROM, 对每个 rank 取比特索引
// q=ROM[rank]; 若 q<N 且信息配额未满, 则将 q 标为信息位 (frozen[q]=0), 直到标满 K 个.
//   —— 自顶向下天然给出"可靠性最高的 K 个 (且索引<N) 位置", 即非冻结集.
// 位 >= N 的 frozen 恒为 1 (置0), 便于后续 u 装配对任意 N 统一处理.
//
// 时延: 可变, 最多 ~NMAX 拍 (一次配置). 混合码长流中同一 (N,K) 只需配置一次,
//       顶层可缓存复用 (见 polar_encode_top).
//
// 端口: start 在 busy=0 时被接受; done 为单拍脉冲, 与 frozen 有效同拍.
// =============================================================================
module frozen_gen #(
    parameter integer NMAX = 1024
)(
    input  wire             clk,
    input  wire             rst_n,
    input  wire             start,
    input  wire [3:0]       n_log,     // log2(N); spec 取 6..10, 也支持更小便于测试
    input  wire [10:0]      K,         // 信息位数 (0..N)
    output reg              busy,
    output reg              done,
    output reg [NMAX-1:0]   frozen     // 1=冻结(u=0), 0=信息位; 位>=N 恒为1
);
    localparam integer RW = $clog2(NMAX);   // 秩位宽 (=10)
    localparam [RW-1:0] RANK_MAX = {RW{1'b1}};   // = NMAX-1 (NMAX 为 2 的幂)

    reg  [RW-1:0] rank;
    wire [9:0]    q;                        // 当前秩对应的比特索引
    reg  [11:0]   need;                     // 尚需标记的信息位数
    wire [11:0]   N = (12'd1 << n_log);     // 码长 N

    polar_reliability_rom u_rom (.rank(rank), .q(q));

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            busy   <= 1'b0;
            done   <= 1'b0;
            frozen <= {NMAX{1'b1}};
            rank   <= {RW{1'b0}};
            need   <= 12'd0;
        end else begin
            done <= 1'b0;
            if (start && !busy) begin
                frozen <= {NMAX{1'b1}};      // 全部先置冻结
                need   <= {1'b0, K};
                rank   <= RANK_MAX;          // 从最高可靠度秩开始
                busy   <= (K != 0);          // K=0 则无需处理
                done   <= (K == 0);          // K=0 立即完成 (全冻结)
            end else if (busy) begin
                if (({2'b00, q} < N) && (need != 0)) begin
                    frozen[q] <= 1'b0;        // 标为信息位
                    if (need == 12'd1) begin  // 刚标满 K 个 -> 完成
                        busy <= 1'b0;
                        done <= 1'b1;
                    end else begin
                        need <= need - 1'b1;
                        rank <= rank - 1'b1;
                    end
                end else begin
                    if (rank == 0) begin      // 扫到底 (K>N 的异常保护) -> 结束
                        busy <= 1'b0;
                        done <= 1'b1;
                    end else begin
                        rank <= rank - 1'b1;
                    end
                end
            end
        end
    end
endmodule

Plain textcontroller beta地址→ beta_mem组合读取→ beta选择/XOR→ beta_mem写口
在阅读RTL时，需要跨多个文件追踪。
但Vivado综合时通常可以跨模块进行优化。只要没有特别设置：
Plain textKEEP_HIERARCHYDONT_TOUCH
综合工具可以展平层次、优化组合逻辑。
因此，跨模块并不天然意味着更慢。

4. 仿真层次化路径比较长
测试平台中可能需要写：
verilogdut.u_datapath.u_sc_llr_mem.llr_mem[i]
而不是直接：
verilogdut.llr_mem[i]
这确实增加了TB的层次访问长度，但只是验证代码稍长，不影响硬件功能。

5. 后续接口修改会牵涉两个文件
例如以后增加两个PE，controller需要输出两组地址，datapath也要接收两组地址。
你需要同时修改：
Plain textsc_controller.vsc_datapath.v
以及封装顶层。
但多PE本来就是控制器、存储器和数据通路的联合改造。即使写成一个大模块，也仍然要修改这些逻辑，只是都在同一个文件中。

二、B/C分开的主要优势
1. 你的模块已经分别验证过
当前已通过：
Plain textB数据通路测试正式C控制器测试N=256测试N=1024测试五种N连续切换测试
这意味着你已经建立了一个可信基线。
如果现在重新写一个融合模块，相当于重新实现：
Plain text地址生成DFS状态机PE控制beta控制叶节点判决输出控制冻结位控制
即使算法不变，也可能重新引入：
Plain text差一拍错误地址偏移错误写使能重叠done脉冲错误最后一个valid/ready握手错误
没有必要承担这个风险。

2. 更容易定位错误
B/C分开时，错误可以快速分类：
B问题
Plain textPE计算错误LLR存储错误beta写回错误u_hat输出错误
C问题
Plain text树遍历错误phase状态错误地址生成错误叶节点顺序错误
如果全部融合进一个模块，出现错误时可能只能看到：
Plain text最终u_hat不对
然后需要在一个很大的always块里排查。

3. 更适合以后增加PE
未来改成：
Plain textPE_NUM=2PE_NUM=4
可以保持：
Plain textSC树遍历框架叶节点控制框架配置接口输出接口
然后主要扩展：
Plain textdatapath并行lane存储器bankcontroller每拍元素步进
模块化结构更利于逐步替换和单独验证。

4. 更适合论文和设计说明
在论文、毕业设计或技术文档中，可以清楚描述：
Plain text控制单元负责SC译码树的深度优先遍历和微操作调度；数据通路负责LLR计算、部分和更新及译码结果存储。
这比“所有逻辑都写在一个模块中”更符合数字系统设计表达。

5. 综合工具不会因为文件分开就一定增加面积
内部wire不会变成FPGA外部端口。
Vivado综合通常会：
Plain text跨层次传播常量删除未使用调试信号合并等价逻辑优化MUX按设置展平层次
因此：
Plain textRTL模块数量多≠硬件面积一定更大
真正决定资源和频率的是：
Plain text存储器实现方式组合读端口数量PE运算路径MUX规模寄存器级数控制逻辑
不是 .v 文件数量。

三、真正融合BC有什么潜在优点？
融合成一个模块并非完全没有好处。
1. 可以减少内部接口代码
所有信号直接写成内部reg/wire，不需要一长串端口映射。
2. 某些局部控制更容易写
例如控制器可以直接访问：
verilogllr_mem[address]beta_mem[address]
不需要经过datapath接口。
3. 小型一次性设计代码可能更短
如果设计固定：
Plain text只支持一个N只使用一个PE以后不扩展不需要单元测试
单模块可能更直接。
但你的设计明显不是这种情况。你需要：
Plain text五种N动态K协议冻结序列后续可能增加PE综合和论文说明
所以融合带来的代码缩短，不足以抵消维护和验证成本。

四、你现在的 sc_decoder_core 已经完成了正确的“合并”
需要区分两种“合并”。
方案A：结构封装合并
Plain textsc_decoder_core├── sc_controller└── sc_datapath
特点：


外部接口少；


内部模块清晰；


已验证B/C可以复用；


综合工具仍可跨层优化。


这就是你现在的方案，推荐保留。
方案B：RTL逻辑完全融合
Plain textsc_decoder_monolithic├── controller状态机├── PE逻辑├── LLR数组├── beta数组└── uhat数组
特点：


文件可能更少；


内部接口名称更少；


但重新验证工作量大；


后续扩展困难；


容易形成超长always块。


目前不推荐。

五、外部端口现在是否已经足够少？
你的 sc_decoder_core 对外大致只有三组接口。
配置接口
verilogconfig_startn_log_cfgk_cfgconfig_readyconfig_busyconfig_doneconfig_error
LLR码块接口
verilogblock_startblock_readyblock_busyblock_donellr_inllr_in_validllr_in_ready
输出接口
verilogu_validu_readyu_bitu_indexu_last
这已经是合理的译码核心接口。
可以进一步减少，但没有必要为了少几个端口牺牲状态可观察性。
例如：
Plain textconfig_busy与config_ready可以理论上合并block_busy与block_ready可以理论上合并load_done可以隐藏
但这些状态信号对于系统调度和调试很有价值。
十几条顶层信号对于一个可配置译码器并不算多。

六、什么时候才值得真正融合？
只有出现以下情况之一时再考虑。
情况1：综合证明模块边界阻碍优化
例如时序报告明确显示：
Plain text由于KEEP_HIERARCHY或DONT_TOUCH无法跨模块优化关键路径
这时首先应该调整综合属性，而不是立即重写RTL。
情况2：最终芯片流程要求单模块交付
某些IP交付规范可能要求一个顶层文件，但仍然可以通过：
verilog`include
或保留子模块一起交付，不必改成单个always块。
情况3：为了特定流水线进行深度融合
例如未来把：
Plain textLLR同步读PE流水线写回流水线controller调度
设计为严格对应的多级流水。
此时可能需要更紧密地重构B/C，但那是性能架构升级，不是单纯为了减少端口。

七、我的具体建议
当前保持三层结构
Plain text第一层：sc_decoder_core    对外提供简洁接口第二层：    sc_controller    sc_datapath第三层：    sc_pe    sc_llr_mem    sc_beta_mem    sc_uhat_mem
不要再写第二套融合译码器。
保存当前版本作为基线
Plain textSC_SINGLE_PE_BC_SEPARATED_PASS
综合时不要随意设置
verilog(* keep_hierarchy = "yes" *)(* dont_touch = "yes" *)
除非调试确实需要，否则让Vivado自行决定是否展平和优化。
后续优化仍在当前结构上进行
先做：
Plain text随机LLR黄金模型多K测试综合资源分析时序报告
综合结果如果满足目标，就完全不需要融合。

最终结论
B/C分开不会构成功能问题，也不会因为内部端口多而占用大量FPGA外部引脚。
你现在最合理的形式就是：
Plain text内部B/C分离+外部sc_decoder_core统一封装
不建议再写一个完全融合的BC模块，因为它不会自动提升性能或减少资源，却会让已经通过的设计重新承担验证风险。
项目里可以正式将当前架构定义为：

分离式控制器—数据通路架构，使用统一译码核心顶层完成接口封装。

这既是工程上更稳妥的结构，也更利于后续多PE、存储器bank化和流水线优化。
