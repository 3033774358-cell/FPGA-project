在极化码（Polar Code）的 SC 译码里，f 运算和 g 运算就是两种“更新置信度”的方法。
先记住一句话：

f 运算用于译码左边的比特，g 运算用于译码右边的比特。


1. 什么是输入的 LLR？
SC 译码通常用 LLR 表示“这个比特更像 0 还是更像 1”。
$L=\ln \frac{P(y|x=0)}{P(y|x=1)}$
可以简单理解为：


$L>0$：更相信这个比特是 0


$L<0$：更相信这个比特是 1


$|L|$ 越大：越有把握


$L$ 接近 0：不确定


例如：


$L=5$：很相信是 0


$L=-4$：很相信是 1


$L=0.2$：稍微偏向 0，但没什么把握



2. f 运算：译码左边比特
假设两个输入 LLR 分别为：
$\alpha,\quad \beta$
那么 f 运算常用的近似公式是：
$f(\alpha,\beta)
=
\operatorname{sign}(\alpha)
\operatorname{sign}(\beta)
\min(|\alpha|,|\beta|)$
也可以写成：
$f(\alpha,\beta)
=
\operatorname{sign}(\alpha\beta)
\min(|\alpha|,|\beta|)$
f 运算怎么理解？
f 运算主要看两件事：
第一，看符号是否相同


两个符号相同：结果为正，倾向于 0


两个符号不同：结果为负，倾向于 1


这其实很像异或判断：
$\alpha$ 倾向$\beta$ 倾向f 的结果00倾向 001倾向 110倾向 111倾向 0
也就是：
$u_0 \approx x_0\oplus x_1$
第二，置信度取较小值
$\min(|\alpha|,|\beta|)$
因为左边比特是由两个信息共同决定的，只要其中一个不可靠，最终判断就不能太可靠。
这可以理解为：

一条链子的强度，取决于最弱的一环。


f 运算例子
例 1
$\alpha=4,\quad \beta=2$
两者都是正数，说明都倾向于 0，所以结果倾向于 0。
幅度取较小值：
$f(4,2)=+2$
结果为 $+2$，表示比较相信左边比特是 0。
例 2
$\alpha=4,\quad \beta=-2$
一个倾向于 0，一个倾向于 1，符号不同，所以结果为负：
$f(4,-2)=-2$
表示左边比特倾向于 1。
例 3
$\alpha=-5,\quad \beta=-3$
两个都倾向于 1，两个 1 异或得到 0，因此：
$f(-5,-3)=+3$
表示左边比特倾向于 0。

3. g 运算：译码右边比特
g 运算的公式是：
$g(\alpha,\beta,\hat u)
=
\beta+(1-2\hat u)\alpha$
其中：


$\alpha,\beta$ 是输入 LLR


$\hat u$ 是前面已经判决出的左边比特


$\hat u\in\{0,1\}$


把公式分开写，就很直观：
当 $\hat u=0$ 时：
$g(\alpha,\beta,0)=\beta+\alpha$
当 $\hat u=1$ 时：
$g(\alpha,\beta,1)=\beta-\alpha$
所以可以简单记成：

左边判成 0，就相加；左边判成 1，就相减。


g 运算怎么理解？
译码右边比特时，左边比特已经译码完成了。
因此，g 运算会利用左边比特的判决结果，把两个接收信息“对齐”，然后再合并。
如果左边比特是 0：
$\beta+\alpha$
说明两路信息方向不需要翻转，直接相加。
如果左边比特是 1：
$\beta-\alpha$
说明第一路信息需要翻转后再合并。

g 运算例子
例 1：左边判为 0
$\alpha=3,\quad \beta=2,\quad \hat u=0$
那么：
$g(3,2,0)=2+3=5$
结果 $5>0$，很相信右边比特是 0。
例 2：左边判为 1
$\alpha=3,\quad \beta=2,\quad \hat u=1$
那么：
$g(3,2,1)=2-3=-1$
结果小于 0，倾向于右边比特是 1。
例 3
$\alpha=-4,\quad \beta=2,\quad \hat u=1$
$g(-4,2,1)=2-(-4)=6$
结果为正，强烈倾向于右边比特是 0。

4. 为什么先 f，后 g？
极化码最基本的编码关系可以写成：
$x_0=u_0\oplus u_1$
$x_1=u_1$
接收端首先看到的是与 $x_0,x_1$ 有关的信息。
译码 $u_0$
因为：
$u_0=x_0\oplus x_1$
所以要把两路信息进行类似“异或”的组合，这就是 f 运算。
译码 $u_1$
译码完 $u_0$ 后，可以利用：
$x_0=u_0\oplus u_1$
以及：
$x_1=u_1$
把两路关于 $u_1$ 的信息合并，这就是 g 运算。
因此顺序是：
$\boxed{\text{先用 f 译左边，再用 g 译右边}}$

5. 完整小例子
假设：
$\alpha=4,\quad \beta=-2$
第一步：用 f 译码左边比特
$L(u_0)=f(4,-2)=-2$
由于结果小于 0，因此判决：
$\hat u_0=1$
第二步：用 g 译码右边比特
因为 $\hat u_0=1$，所以：
$L(u_1)=g(4,-2,1)$
$=-2-4=-6$
结果小于 0，因此：
$\hat u_1=1$
最终译码结果为：
$(\hat u_0,\hat u_1)=(1,1)$

6. 最简单的记忆方法
f 运算
$f(\alpha,\beta)
=
\operatorname{sign}(\alpha\beta)
\min(|\alpha|,|\beta|)$
记成：

符号做异或，大小取最小。



同号得正


异号得负


幅度取较小值


g 运算
$g(\alpha,\beta,\hat u)
=
\beta+(1-2\hat u)\alpha$
记成：

左边是 0 就加，左边是 1 就减。

即：
$\hat u=0:\quad \alpha+\beta$
$\hat u=1:\quad \beta-\alpha$

7. 一句话总结
$\boxed{f：根据两路信息的“异同”来译左比特}$
$\boxed{g：利用已经译出的左比特，合并两路信息来译右比特}$
其中：


f 运算比较谨慎，所以置信度取较小值；


g 运算利用已有判决，所以可以把两路置信度直接相加或相减。

MCS（Modulation and Coding Scheme，调制与编码方案），简单理解就是：

无线通信系统根据当前信道情况，决定“用什么调制方式 + 用什么编码速率”来传输数据。

它决定了一次传输能发送多少数据。

1. 为什么需要 MCS？
无线信道不是一直一样的。
比如：


手机离基站很近：


信号强


干扰小


可以发送更多数据

信号弱


噪声大


容易出错




如果一直使用高速率：

数据发得快，但是错误很多。

如果一直使用低速率：

很稳定，但是浪费信道。

所以通信系统需要动态调整：
$\boxed{\text{信道好} \rightarrow \text{高MCS}}$
$\boxed{\text{信道差} \rightarrow \text{低MCS}}$

并行 SC 译码（Parallel SC Decoder），简单理解就是：

把传统 SC 译码中“一个比特一个比特串行判断”的过程，改成多个节点同时计算，从而提高译码速度。

先理解普通 SC，再理解并行。

1. 普通 SC 译码为什么慢？
极化码的 SC（Successive Cancellation，连续消除）译码特点：

必须按照比特顺序依次译码。

例如：
$u_0,u_1,u_2,u_3$
SC流程：
代码先译 u0 ↓得到结果 ↓再译 u1 ↓得到结果 ↓再译 u2 ↓得到结果 ↓再译 u3
也就是说：
$\boxed{\text{前一个比特的结果决定后一个比特}}$
所以它叫：
连续消除译码。

2. SC译码树结构
极化码译码实际上是一棵树。
例如：
N=8：
代码                 根              /      \            f          g          /   \       /   \        f      g    f      g       / \    / \  / \    / \      u0 u1 u2 u3 u4 u5 u6 u7
每个节点都有：


f运算


g运算


传统SC：
深度优先遍历：
代码左边走到底↓译u0↓回来↓译u1↓再回来...

3. 什么是并行SC？
核心思想：

不要每次只计算一个节点，而是同时计算多个节点。

例如：
传统：
代码f |u0 |g |u1 |g |u2
一次只处理一个。
并行：
代码       f    /     \  f         g / \       / \u0 u1    u2 u3
多个节点同时计算。

4. 并行SC主要并行在哪里？
主要有三种方式：

（1）节点级并行（Node Parallelism）
利用译码树中：
同一层多个节点可以同时计算。
例如：
N=8：
第二层：
代码      root    /      \  node1   node2
node1和node2：
可以同时计算。
硬件：
代码       控制器     /        \ f计算单元    g计算单元     \        /     多个LLR处理

（2）运算级并行
f/g里面本身也可以并行。
例如：
f：
$L_i=f(\alpha_i,\beta_i)$
有很多：
$i=0,1,2,...,N/2-1$
可以：
同时计算：
代码f0f1f2f3...
而不是：
代码f0→f1→f2

（3）比特并行
一次译多个bit。
例如：
传统SC：
代码u0u1u2u3
并行SC：
代码[u0,u1,u2,u3]一起译
但是：
这里会破坏SC严格顺序。
所以通常需要特殊方法。

5. 为什么不能完全并行？
因为：
SC存在依赖关系。
比如：
译：
$u_5$
需要知道：
$u_0,u_1,u_2,u_3,u_4$
因为g运算：
$g(\alpha,\beta,\hat u)
=
\beta+(1-2\hat u)\alpha$
里面有：
$\hat u$
也就是：
之前译出的结果。
所以：
完全并行：
❌ 不可能。

6. 常见并行SC优化方法
方法1：展开SC（Unrolled SC）
把整个译码树展开。
例如：
传统：
代码一个处理器重复计算
展开：
代码f f f g g g同时存在
优点：
速度极快。
缺点：
硬件资源巨大。

方法2：流水线SC（Pipelined SC）
类似CPU流水线。
例如：
代码周期1:计算f周期2:计算g周期3:判决
多个数据块同时进入。
优点：
提高吞吐量。

方法3：Fast-SSC
这是现在很常用的方法。
发现：
有些节点：
例如：
Rate-0节点：
全部冻结：
代码000000
不用计算。
Rate-1节点：
全部信息位：
直接硬判。
所以：
跳过大量树搜索。
速度大幅提升。

7. SC和并行SC区别
SC并行SC译码方式串行部分并行速度低高硬件面积小大功耗低高实现难度简单复杂适合低速设备高速通信

8. 一个直观比喻
普通SC：
像考试：
代码第1题做完才能做第2题第2题做完才能做第3题
速度慢。
并行SC：
像：
代码数学老师做选择题英语老师做阅读题物理老师做计算题同时完成
但是：
如果第2题必须知道第1题答案：
仍然不能完全同时。

9. 和5G关系
5G NR中的Polar码：
通常采用：


CRC辅助SCL译码


Fast-SSC优化


高度并行硬件结构


因为5G要求：


控制信道延迟低


吞吐率高


所以：
实际硬件不是最原始SC，而是：
$\boxed{
\text{Fast-SSC + SCL + 并行硬件架构}
}$

一句话总结：

并行SC译码就是利用极化码译码树中可以同时计算的f/g节点，把原本逐比特的SC流程改造成多节点、多运算单元同时工作，在保持SC思想的基础上提高吞吐率。
